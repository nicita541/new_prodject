# Bind proposed events to retained source spans

## Goal

Make the primary montage proposal preserve its own stated events, including silent
actions, before native/source and cut-only checks. Keep ordered multiple cut
groups and useful shortening. Do not force continuous extracts or retain all
uncertain footage. Add no model stage/role or repair loop.

## Constraints

Preserve all legacy proposals/readers and exact immutable raw replies. New proposal
proofs are hypotheses, never semantic approval. Native images/IDs differ from
preview observations: keep them separate. Keep original PTS/owner/SHA validation,
measured actual geometry, full independent source/viewer gates and one shared
editorial repair budget. All experiments use only the authorized120s excerpt.

## Implementation

1. Introduce experimental proposal_policy version1, separate from source-join v2.
   No production default switch until one fixed source experiment demonstrates
   useful selection and factual inspection. Absent policy keeps the old schema.
2. Add source-backed setup/development/payoff beats to the existing proposal
   response. A speech beat quotes its exact own unit; appearance cites an owned
   image; change cites ordered different-pixel before/after observations and a
   contiguous whole-unit span. Description is display text, not evidence.
3. Require every beat span to be fully inside ONE selected core group, and inside
   one actual compiled cut. Retaining only endpoints while cutting the middle
   cannot represent that change. Multiple development beats/groups remain valid.
4. Keep proposal observations separate from native case.frames, persist their
   owned facts in the private case, and bind resolved beat evidence to timeline.
   Review payload never treats proposer claims as an authoritative verdict.
5. Observe original-shot first/last frames as indivisible temporal pairs before
   optional midpoint/motion detail; preserve quiet chronological coverage under
   tight known pre-dispatch capacity. Use actual decoded PTS, not requested hints.
6. Restoration must preserve/revalidate the binding; trimming that makes it stale
   stops without a new semantic loop. Continuous technically safe draft fallback
   keeps no fabricated beat proof and cannot acquire ready/export authority.

## Validation

Pure regressions: legacy dispatch, own-source/owner/frame/quote checks, reversed or
identical change observations, disconnected catalog spans, omitted middle despite
retained endpoints, multiple separated groups, actual audio geometry preserving
beats, stale restoration/trim binding and safe draft fallback. Sampling: actual
shot endpoints, single-frame appearance, quiet coverage, pair atomicity under
capacity and unknown dispatch never causing resampling.

One predeclared new proposal on the same source/hypothesis and ordinary45–90/120
preferences. Do not send old cuts/verdict/diagnosis/timestamps as model hints.
Inspect the sampled standing/fallen states and fresh chosen source spans offline.
Then ordinary native+blind qualification, compilation/render, output-first review,
source comparison and exact warm reuse with transports/startups forbidden. No
unchanged question replay until approval. A false or dull montage fails editorial
acceptance even with a mechanically valid event binding.

## Risks and rollback

The model can misinterpret pixels or choose uninteresting beats. This representation
only prevents its own bound event from being silently removed; it does not prove
all necessary events were identified. Richer observations have input cost; measure
that against avoided follow-up work, never claim a prompt-only causal comparison
when schema/sampling also change. Keep the production default unchanged until the
fixed experiment is reviewed. Archive and remove an ineffective experiment rather
than accumulating dormant policies or weakening gates.
