# KADR Studio frontend

Единственный интерфейс — `public/studio-edition.html`, `studio-edition.css`, `studio-edition-app.js` и `studio-live-bridge.js`. Данные поступают из FastAPI; при недоступном сервере показывается ошибка подключения, вымышленные проекты и результаты не создаются.

При открытии проектов адаптер запрашивает `/api/jobs?summary=true`: статусы и готовые файлы без чтения подробных диагностик старых заданий. На экране обработки параметр `progress_job_id` включает подробный прогресс выбранного монтажа. Обычные `/api/jobs` и `/api/jobs/{id}` сохраняют полный ответ для других клиентов, включая MCP.

Настройки монтажа показывают импорт исходника, три варианта кадра и компактные строки анализа и музыки. Выбор карточки открывает отдельное окно с каналом и подписью; дополнительные параметры анализа и музыки также открываются в окнах. «Готово» возвращает к настройкам с сохранением черновика; кнопка «Сохранить» записывает настройки на сервер.

Режим запуска выбирается стрелкой возле нижней кнопки: обновить монтаж по изменениям, пересобрать только план или выполнить полный монтаж. Пересборка плана использует сохранённый анализ без моделей и экспорта. Перед запуском Studio проверяет `processing_modes` в `/api/health`: старый сервер нужно перезапустить, иначе выбор режима мог бы быть проигнорирован и привести к полному прогону.

Оформление сохраняется и применяется к готовым Shorts через отдельный экспорт до 100 частей. Старые MP4 остаются на диске; просмотр и скачивание используют только завершённый экспорт с совпадающей версией плана. Изменения настроек сбрасывают устаревший предпросмотр. Старые ссылки `/#episode/<id>/review/<job>` открывают выбранный монтаж через актуальный маршрут.

После нажатия применения сразу показывается начало обновления, затем постоянный статус очереди/подготовки/оформления и прогресс внутри ролика. Сообщение об успехе появляется после завершения экспорта и загрузки новых файлов. Оформление использует сохранённые чистые части; неизменённые готовые части копируются без кодирования. Для старых проектов чистые части создаются один раз, а старые экспорты без контрольного отпечатка один раз пересобираются перед дальнейшим повторным использованием.

`npm run build` вызывает `scripts/build-studio.mjs`: проверяет синтаксис JavaScript, копирует Studio в `dist` и удаляет устаревшие продукты frontend-сборки только внутри `dist`. Для сборки достаточно portable Node в `../tools/node`; React, Vite и TypeScript не используются. `npm run dev` следит за изменениями `public` и пересобирает ту же Studio; HTTP предоставляет основной backend на `127.0.0.1:8765`.

Из корня проекта:

```powershell
& tools/node/node.exe frontend/scripts/build-studio.mjs
& tools/node/node.exe frontend/scripts/check-studio.mjs --lint
& tools/node/node.exe frontend/scripts/check-studio.mjs
```

Последняя команда выполняет две проверки Studio в jsdom. Если тестовые зависимости отсутствуют, установите их проектным `scripts/npm.cmd ci --prefix frontend --no-audit --no-fund`. Это единственная dev-зависимость; она не нужна для работы приложения или сборки.

API-адаптер `studio-live-bridge.js` отвечает за запросы, нормализацию и загрузку реальных записей. `studio-edition-app.js` отвечает за экраны, действия пользователя и воспроизведение. Backend-маршруты Studio принадлежат `app/studio_routes.py`. Удалённые `/legacy`, `/react-debug` и reference HTML возвращают 404. Подробная карта: [docs/audit/architecture.md](../docs/audit/architecture.md).
