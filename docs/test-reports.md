# Проверка и отправка тестовых отчётов

1. Переключитесь на ветку `fix/montage-stability` и выполните `git pull`.
2. Запустите `ПРОВЕРИТЬ_ПРОЕКТ.bat` двойным щелчком.
3. Тесты Python, React и проверка FFmpeg выводят итоговый статус PASS/FAIL/SKIP.
4. Подробные логи остаются в `temp/verification-reports/<ID>`. Краткий отчёт и очищенные, ограниченные по длине выдержки журналов публикуются в отдельной ветке `test-reports` в каталоге `runs/<ID>`.
5. Для полного набора тестов запустите `ПРОВЕРИТЬ_ПРОЕКТ.bat -Full`. Для запуска без публикации — `ПРОВЕРИТЬ_ПРОЕКТ.bat -NoUpload`.

Нужны Git с настроенным `origin` и авторизацией с правом записи, Python, npm с установленными зависимостями `frontend/node_modules` и portable FFmpeg. Отсутствующие компоненты маркируются SKIP, а не PASS. При ошибке публикации отчёт сохраняется локально. Скрипт не меняет кодовую ветку и не загружает исходные серии или видео.

**Конфиденциальность:** несмотря на отсечение известных форматов токенов и путей, выдержки логов потенциально могут содержать имена файлов и другую частную информацию. Отправка осуществляется в приватный репозиторий, но перед запуском следует убедиться, что тесты не работают с чувствительными материалами. Полные необработанные логи в GitHub не отправляются.

### Тестирование параллельно с работающим монтажом

Из каталога `F:\new_prodject-fixed` можно запускать **`ПРОВЕРИТЬ_ПРОЕКТ.bat -Quick`**. Этот режим:

- Использует портативный Python из другого связанного Git worktree, если в новой рабочей папке его нет; можно явно указать путь аргументом `-PythonExe "F:\new_prodject\tools\python\python.exe"`.
- Перенаправляет временные каталоги и кеш компиляции Python в текущий worktree, а не в папку работающего монтажёра.
- Запускает ограниченные проверки Python (музыка, задания, роутинг), React-тесты, lint, сборку и диагностические проверки присутствующих FFmpeg/FFprobe. **Не запускает модели и не запускает реальный монтаж**.
- При отсутствующих `frontend/node_modules` помечает React-проверки как SKIP. Для них в новой папке один раз выполните `cd frontend; npm ci --no-audit --no-fund; cd ..`.
- Отправляет краткий отчёт в ветку `test-reports`, как и обычный режим.

**Для независимого Python-окружения** в папке второго Worktree выполните:
```powershell
cd F:\new_prodject-fixed
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.in
.\ПРОВЕРИТЬ_ПРОЕКТ.bat -Quick
```
Скрипт автоматически использует `.venv\Scripts\python.exe`, если он есть. Это не устанавливает пакеты в Python первой работающей папки и не скачивает веса моделей. Создание окружения и установка библиотек требуют памяти/диска, но не запускают обработку аниме.

**Важно:** статус Python-тестов определяется по коду завершения *и* итоговому сообщению pytest. Ошибки импорта и сбора тестов никогда не должны считаться успешной проверкой.

Это не полноценное end-to-end тестирование. Быстрый режим снижает нагрузку, но сборка React и Python-тесты могут немного замедлить обработку первой серии. **Не создавайте символическую ссылку на папку `data` исходного проекта и не запускайте второй процесс обработки на тех же файлах.**

### Отсутствует Pillow (PIL)

Если в логе `python_tests.out.txt` написано `ModuleNotFoundError: No module named 'PIL'`, установите только недостающую библиотеку во **вторую** виртуальную среду:

```powershell
cd F:\new_prodject-fixed
.\.venv\Scripts\python.exe -m pip install Pillow
.\ПРОВЕРИТЬ_ПРОЕКТ.bat -Quick
```

Скрипт дополнительно проверяет PIL перед запуском тестов и честно показывает отсутствие библиотеки, вместо ложного `PASS`.
