# Отчёты проверок KADR Studio

Актуальная рабочая ветка: `codex/dramatic-montage`. Запускайте проверки из папки
`F:\new_prodject\ТЕСТЫ` двойным щелчком, после обновления локальной ветки.

## Проверка без ИИ

`1_ПРОВЕРКА_БЕЗ_ИИ.bat` запускает все Python-тесты, тесты React,
сборку, lint, FFmpeg/FFprobe и 180-секундную медиа-проверку:
реальное кодирование MP4, субтитры, музыку, повторное использование кэша,
повреждение и восстановление SRT, finishing и API Range.
Это технический E2E на **синтетическом видео** и с **фиктивными смысловыми
решениями**: настоящий Whisper/ASR, VLM и DeepSeek не запускаются.

## Полная проверка с локальными моделями

`2_ПОЛНАЯ_ПРОВЕРКА_С_ИИ.bat` сначала делает техническую проверку,
затем открывает диалог выбора настоящего сюжетного видео с аудио.
Из длинной серии извлекает отдельный 180-секундный участок;
исходник не меняется. Далее запускает реальный локальный ASR и VLM,
планирование, рендеринг и проверку восстановления из кэша.

Для выбора другого участка видео (например, после опенинга):

```powershell
& ".\ТЕСТЫ\2_ПОЛНАЯ_ПРОВЕРКА_С_ИИ.bat" -RealSource "F:\new_prodject\data\imports\episode.mp4" -StartSeconds 300
```

**Для полной проверки недопустима передача готового транскрипта
(`-RealTranscript`): ASR обязан реально отработать.**
Если модель не запускается, нет исходного видео или качество не проходит
проверку, отчёт будет FAIL, а не ложный PASS. Первый прогон локальной
модели может длиться значительно дольше технического.

## Где результаты

Локально, по идентификатору запуска:
- `temp\verification-reports\<run_id>\checks.json` и `summary.md`
- `logs\tests\<run_id>\` — полные диагностические логи

После любой из двух проверок очищенная сводка автоматически публикуется
в GitHub, **в отдельную ветку `test-reports`**, по пути
`runs/<run_id>/`. Работа с отчётами не меняет текущую ветку кода,
не публикует видео, транскрипты или полные логи моделей.
Для проверки ошибок модели в GitHub публикуются только итог и
безопасная структурированная сводка этапов; подробные логи остаются на ПК.
Логи технических тестов публикуются в сокращённом виде после очистки,
но перед запуском с чувствительными данными учитывайте, что эвристическая
очистка текстов не гарантирует удаление всех приватных строк.

Нужны Git с настроенной авторизацией на запись, Python-зависимости,
`frontend/node_modules`, установленный portable FFmpeg. Если зависимости
нет, статус будет SKIP/INCOMPLETE вместо PASS. Ошибка отправки отчёта
не стирает локальный результат и приводит к отдельному коду выхода,
если сам тест завершился без ошибок.

## Отладка без загрузки и без тяжёлой обработки

Из PowerShell можно вызвать скрипт напрямую:

```powershell
.\scripts\verify_project.ps1 -Quick -NoUpload
```

`-Quick` запускает сокращённые тесты без 180-секундного рендера,
`-NoUpload` отключает отправку. В отличие от `-Quick`, обычный BAT
«без ИИ» запускает **полный технический конвейер**.

Скрипты находятся в `scripts/verify_project.ps1`,
`scripts/full_pipeline_3min.py`, `scripts/prepare_real_test_video.py`.
