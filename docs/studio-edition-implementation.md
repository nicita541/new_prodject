# КАДР STUDIO — Studio Edition

Рабочий интерфейс — единственная KADR Studio, связанная с FastAPI. HTML/CSS и основной JavaScript находятся в `frontend/public`; `studio-live-bridge.js` загружает настоящие данные. `app/studio_routes.py` обслуживает её assets и ссылки экранов, `app/finishing.py` владеет finishing API, `app/studio_render.py` выполняет повторный рендер. Демонстрационные и запасные интерфейсы удалены. Сборка и проверки: [frontend/README.md](../frontend/README.md).

## Маршруты редактора

- `/studio` — выбрать готовую серию
- `/episode/<uuid>/finishing/<uuid-работы>` — редактор после автоматического монтажа
- `/episode/<uuid>/review/<uuid-работы>` — проверка исходного монтажа, ссылка «Оформление»

В левом меню — «Проекты» и «Корзина». Выберите проект и серию; настройки, монтаж, Shorts и оформление открываются в контексте этой серии. Экран ответов API и кнопки сырых JSON удалены. Диагностика доступна через отдельный [MCP для разработки](mcp.md).

В редакторе есть выбор Shorts, субтитры (редактирование времени и текста, цвет, размер, позиция drag и стрелками, пресеты), аудио (импорт, стриминг, громкость, режим треков, fade, ducking), кадр (полный кадр, крупный план или карточка публикации; brightness, размытие фонового слоя, vignette), предпросмотр и отдельный экспорт. Масштаб регулируется для обычных композиций; карточка сохраняет весь кадр.

## Карточка публикации

В настройках серии выберите «Карточка публикации» в блоке «Оформление Shorts», затем вариант «Компактная» или «Пост». Заполните название канала и подпись; для поста можно также указать `@имя`. Сохраните настройки или запустите монтаж. Тёмная карточка содержит канал, подпись и видео в этом порядке; вокруг остаётся мягкий фон. Название и имя ограничены 60 символами, подпись — 180. Счётчики лайков, просмотров и даты не создаются.

Для готовых Shorts откройте «Оформление» → «Кадр» → «Карточка публикации». Проверьте результат кнопкой «Создать предпросмотр», затем «Экспортировать видео». Оформление создаёт новый MP4 из исходных фрагментов без повторного распознавания и анализа. Возврат к «Полному кадру» или «Крупному плану» выключает карточку.

## HTTP-контракты

| Метод | Путь | Действие |
|---|---|---|
| GET/PUT | `/api/episodes/{id}/finishing` | Профиль оформления, version=1 |
| GET/PUT | `/api/jobs/{id}/parts/{index}/captions` | Правки реплик по частям и revision |
| PUT | `/api/jobs/{id}/finishing/state` | Атомарное сохранение профиля и изменённых реплик выбранного job |
| POST | `/api/jobs/{id}/previews` | Фоновая задача предпросмотра до 10 с |
| GET | `/api/jobs/{id}/previews/{preview_id}` | Статус предпросмотра |
| GET/HEAD | `/api/jobs/{id}/previews/{preview_id}.mp4` | MP4 с поддержкой Range |
| POST | `/api/jobs/{id}/exports` | Новый повторный экспорт без анализа AI |
| GET | `/api/exports/{export_id}` | Статус и ссылки результата |
| GET/HEAD | `/api/exports/{export_id}/files/{filename}` | MP4/SRT с поддержкой Range |
| GET/HEAD | `/api/music/tracks/{filename}/stream` | Аудио с поддержкой Range |
| POST | `/api/music/import` | Бинарная загрузка и FFprobe-проверка трека |

## Безопасность и изоляция

- Нельзя изменять оригинальные `job_dir/plan.json` и `job_dir/output/part_*.mp4` через Studio Edition.
- Новые экспорты создаются в `job_dir/finishing/exports/<ID>/output`. Предпросмотры — в `job_dir/finishing/previews/<ID>/output`.
- Профили оформления сохраняются в `JobManager.root/finishing/episodes/<ID>.json`; реплики — `job_dir/finishing/captions_<index>.json`.
- При рендере повторно используются исходные cuts; нейросетевые модели и платный API не запускаются.
- Экспорт и предпросмотр запрещены, пока внутри этого сервера выполняется основная обработка.
- Ограничения Pydantic на поля и координаты, проверка реплик по длительности, запрет путей извне, ограничение загрузки музыки, FFprobe-проверка, временная запись и атомарное переименование.
- Экспорт фоновой задачей; статус доступен по API. После перезапуска сервера незавершённую задачу нужно запускать заново.

## Два уровня предпросмотра

1. **Браузерный** — мгновенное наложение изменяемого текста и частичных визуальных эффектов. Для карточки используется исходное видео с переходами по выбранным cuts, чтобы готовая рамка не накладывалась повторно. В обычной композиции используется готовый MP4, который может содержать запечённые старые субтитры. Браузерный слой не гарантирует пиксельного совпадения с новым результатом.
2. **Серверный** — кнопка «Создать предпросмотр»; строится из исходных cuts с новыми титрами, кадрированием и звуком и служит достоверной проверкой перед экспортом.

## Автоматические тесты

GitHub Actions `KADR production checks` выполняет две Studio DOM/API проверки, проверку синтаксиса, native Node сборку и Python-регрессии. Локальные команды — в [инструкции проверок](../ТЕСТЫ/README.md); временные файлы остаются в `F:\new_prodject`. Проверки интерфейса используют изолированные fixtures и не считаются доказательством качества анализа настоящей серии. Для сохранения отчётов локально используйте `-NoUpload`.

## Ограничения

Это не полноценная нелинейная монтажная станция: `cuts` намеренно остаются результатом автоматического монтажа, в Studio Edition меняется оформление и повторно кодируется видео. Фоновые задачи пока не переживают перезапуск как возобновляемые процессы, а браузерный предпросмотр приблизителен до получения серверного MP4. Полная проверка настоящей серии и качества смысловой связности — отдельная задача.
