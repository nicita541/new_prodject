# Журналы KADR Studio (папка logs)

Все журналы остаются локально на компьютере в `F:\new_prodject\logs`.
Приложение и тесты **ничего не отправляют** в ChatGPT автоматически.
Отправляйте нужную папку/архив вручную, только после просмотра на наличие
личной информации (например, названий файлов и текстов ошибок).

## Где искать ошибку

- `logs/LATEST.txt` — путь к последней диагностической сессии.
- `logs/studio/<дата-время_pid>/readable-<pid>.log` — понятный журнал
  работы сервера, Python-обработчика и ошибок с трассировками.
- `logs/studio/<дата-время_pid>/events-<pid>.jsonl` — структурированные
  события со временем UTC, `action`, `stage`, `job_id`, кодом ошибки,
  длительностью, результатом. Сервер и дочерний обработчик используют одну
  папку сессии, но каждый пишет **в свой файл по PID**, без смешивания строк.
- `logs/tests/<дата-время_pid>/` — сквозной 3-минутный тест и его этапы.
- `logs/tests/<runid>/` — `verify_project.ps1` с отдельным
  `python_tests.out.txt`, `react_build.err.txt` и прочими выводами.
- `logs/startup.log` — ошибки начальной проверки `start.bat` (когда Python
  или интерфейс не удалось запустить).

## Какие события записываются

1. Старт Studio, состояние порта, запуск/остановка сервера.
2. HTTP-действия интерфейса (метод, **шаблон маршрута**, код ответа,
   длительность), нажатия на кнопки `data-action`, ошибки JS и промисов.
3. Начало и прогресс анализа: расшифровка, сцены, смысловой анализ,
   контроль качества, планирование, рендер. `job_id` объединяет события.
4. Запуск FFmpeg/FFprobe, время завершения, код ошибки и `detail_log` —
   путь к полному техническому журналу процесса.
5. Завершение задания или нештатная остановка, ошибки сервера и
   FFmpeg-предпросмотра. При Python-ошибке сохраняются тип и трассировка.
6. При тестах — отдельные `check_start/check_passed/check_failed`,
   кэш-попадания и пересборка после повреждения.

Не записываем содержимое полей форм, текст вводимых субтитров, тела HTTP,
заголовки Authorization, ключи и промпты. Подозрительные токены и
`api_key=...` дополнительно маскируются. Некоторые сообщения об ошибках
могут раскрывать локальные имена файлов — перед отправкой проверьте их.

## Дополнительная глубокая диагностика конкретной серии

Папка по `job_id`:

```
data/jobs/<job_id>/diagnostics/pipeline/timeline.jsonl
data/jobs/<job_id>/diagnostics/pipeline/decisions.jsonl
data/jobs/<job_id>/worker.log
data/jobs/<job_id>/render/**/process_*.log
```

Файлы по отдельным задачам и FFmpeg не перемещаются и не удаляются;
`logs` содержит удобную сводку и подсказки, где они лежат.

## Найти ERROR за последний запуск

Откройте `открыть_логи.bat` или в PowerShell:

```powershell
cd F:\new_prodject
Get-Content .\logs\LATEST.txt
Get-ChildItem .\logs -Recurse -Filter "events-*.jsonl" |
  Select-String '"level": "ERROR"'
```

Чтобы увидеть ошибки задания по ID (замените UUID):

```powershell
Get-ChildItem .\logs -Recurse -Filter "events-*.jsonl" |
  Select-String 'UUID_ЗАДАНИЯ'
```

Для следующего сообщения мне обычно хватит архива **последней папки**
`logs/studio/...` или `logs/tests/...` и краткого описания, что вы
нажимали. Для дефекта FFmpeg иногда потребуется отдельно приложить
`process_*.log` из `detail_log`. Никогда не отправляйте `.env` и ключи.

## Ограничения

События зафиксированы для известных действий интерфейса и этапов
конвейера; **не записываются движения мыши по пикселям, персональные
данные форм и внутренние мысли нейромодели**. Логи записываются локально
и со временем занимают место. Автоматическую очистку пока не включали,
чтобы не уничтожить материал для анализа. Удалять устаревшие сессии
из `logs/studio` и `logs/tests` можно вручную, когда они не нужны.
