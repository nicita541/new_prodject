# Полный тест KADR Studio на трёхминутном видео

Это **сквозной тест**, а не набор изолированных unit-тестов. Все результаты
записываются только в папку проекта `temp/full-pipeline-3min/`. Исходные
серии пользователя и готовые задания не изменяются. В репозиторий не
добавляется большой бинарный MP4: он создаётся FFmpeg при запуске теста.

## Тест 1. Автоматический технический (без ИИ)

В PowerShell из `F:\new_prodject`:

```powershell
.\test_full_pipeline_3min.bat
```

Что выполняется:

1. Создаётся **настоящий декодируемый MP4 на 180 секунд**, 320×180,
   с движущейся тестовой картинкой и настоящей AAC-аудиодорожкой.
2. FFprobe проверяет длительность, кадры и наличие аудио.
3. Подготавливается **явно синтетическая таблица решений** для шести
   тестовых временных интервалов и тестовые русские реплики.
   **ASR, DeepSeek, Whisper и VLM в этом режиме НЕ запускаются.**
   Настоящий контроль смысловых доказательств для этих несуществующих
   персонажей здесь только протоколируется, не блокирует технический тест.
4. Проходит реальный `app.pipeline.run_job`: планирование,
   финальный монтаж FFmpeg, наложение субтитров, фоновая музыка 15 %,
   генерация MP4/SRT, проверка полученного видео и звука.
5. Выполняется **второй полный запуск** того же задания. Все части должны
   попасть в валидированный кэш, хэши выходных файлов должны совпадать.
6. В тестовом SRT намеренно записываются повреждённые данные.
   Выполняется третий запуск: повреждение должно обнаружиться, часть
   пересобраться, а SRT восстановиться.
7. Запускается **реальный финальный FFmpeg-предпросмотр** с обновлённой
   подписью, музыкой и масштабом 90 %. Снова проверяются выходные файлы.
8. Проверяются реальные API Studio: чтение задания и плана, отдача
   исходного видео, MP4 и SRT по HTTP Range и HEAD, правильные размеры файлов.
9. Проверяется, что исходный 180-секундный MP4 не изменился.

Все проверки обязательны. При дефекте программа вернёт код ошибки и сохранит
`report.json`, `e2e-progress.jsonl`, `timings.json`,
`final_quality_gate.json` и локальные журналы FFmpeg.

**Важно:** этот режим подтверждает работу реального видео-конвейера,
**но не доказывает качество распознавания реального аниме**.

## Тест 2. Настоящий полный анализ (нужны локальные модели)

Поместите внутрь `F:\new_prodject` трёхминутное MP4 с реальной историей
и разборчивыми русскими диалогами. Запустите:

```powershell
.\test_full_pipeline_3min.bat -Mode real -Source "F:\new_prodject\data\imports\мой_тест_180сек.mp4"
```

Этот режим использует существующий **настоящий** путь
`scripts/run_production_raw_quality.py` с `render=True`:
декодирование, Whisper ASR, анализ кадров локальной моделью,
проверку сюжетных связей, планирование, строгий quality gate,
FFmpeg и финальные артефакты. При ошибке модельного анализа,
критическом пропуске контекста, недоступности модели, нехватке ресурсов
или ошибке рендера тест завершится с кодом 1 и сохранит подробный отчёт.
**Никакая модель и API не имитируются в реальном режиме.**

Если у вас уже есть настоящая расшифровка слов с таймкодами:

```powershell
.\test_full_pipeline_3min.bat -Mode real -Source "F:\new_prodject\data\imports\мой_тест_180сек.mp4" -Transcript "F:\new_prodject\data\imports\моя_расшифровка.json"
```

При переданном Transcript проверка Whisper **не выполняется** — тест
начинает модельный анализ по предоставленным словам. Для проверки и ASR,
и визуальной части **не указывайте Transcript**.

После успешного полного прогона программа запускает **ту же серию ещё раз**:
новых запросов к модели быть не должно, все MP4 должны браться из
валидированного кэша и иметь прежние SHA-256. Если хоть один из этих
контрольных пунктов не выполнится, тест считается проваленным.

Не запускайте реальный режим на тестовой картинке с синусоидой:
на ней отсутствуют персонажи, история и речь; корректный quality gate
вправе её отклонить.

## CI

Отдельный workflow `KADR 3-minute full pipeline E2E` запускает
технический тест на GitHub Actions при изменении самого тестового
сценария, вручную и по субботам. Он использует настоящий Linux FFmpeg,
но не скачивает модели и не обращается к платным API.
В `Actions → Artifacts` остаётся ZIP с отчётом, даже когда тест не прошёл.

Windows и локальные модели проверяются командой выше на пользовательском ПК,
а не подменяются успешным Linux CI.

## Приёмка и ограничения

**Должно пройти:** генерация 180 сек; MP4 содержит видео и звук;
все выходные части валидны; SRT не пустые; фоновая музыка присутствует;
повторный запуск использует кэш; повреждённый SRT инвалидирует кэш;
в финальном FFmpeg-предпросмотре учитываются выбранные новые субтитры.

**Не гарантирует автоматически:** эстетическое качество монтажа,
содержательность сцены, качество ASR для русского дубляжа и правильность
всех решений локальной модели. Это проверяется отдельным реальным
прогоном и просмотром сравнений исходника с результатом.

Отчёт требует `status=passed` и содержит не только зелёный статус,
но и список этапов, время выполнения, отдельные хэши и тип ошибки
при сбое. Не выдавайте синтетический режим за доказательство работы ИИ.
