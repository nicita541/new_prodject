### Решение по eyecatch

Пользователь выбрал **оставить текущую эвристику и только отметить риск**. В этом аудите её поведение не изменяется. Условие воспроизводится из кода: длина видео ≥300 секунд, событие в зоне 35–65%, длительность 1,5–14 секунд, низкая плотность речи; отсутствие слов само достаточно для кандидата. Применение ставит `kind=eyecatch`, `importance=0`, очищает `selected_ranges`. Здесь нет проверки изображения/брендинга. Это доказанный риск эвристики, **не доказанная потеря конкретной сцены пользовательского видео**. Оба коротких бенчмарка меньше 300 секунд и этот путь не проверяют.

### Что не следует делать по одному замеру

Не ослаблять quality gate ради готового MP4, не смешивать холодный и кэшированный запуск, не складывать вложенные retry/startup интервалы, не обещать пропорциональное время полной серии. Удаление модели, замена провайдера или пакетирование запросов требует проверки итогового содержания, а не только FPS/токенов.

## Что осталось проверить отдельно

Редакторская приёмка полной серии; другие жанры/источники; MKV/неподдерживаемые браузером кодеки; чистая установка на другом ПК; работа без Vulkan/CUDA с CPU fallback; отмена настоящего большого экспорта и восстановление после аварийного завершения. Эти проверки не маскируются под выполненные тестами коротких фрагментов.
