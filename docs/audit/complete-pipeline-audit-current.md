## Что в присланном аудите неверно или требует оговорки

1. **«Ошибка VLM сохраняет всё событие».** Текущий `minimal_semantic_context` оставляет пересечение прежнего выбора с конкретными положительными доказательствами. Он выставляет `whole_scene_last_resort=false`; неизвестный материал не становится принятым.
2. **«Global review ставит всем importance=4».** В `validated_event` это резервное значение для отсутствующей/неверной оценки, а не обязательное решение для каждого события. Само завышение реальных оценок модели надо проверять на её ответах.
3. **«Каждая смена настроек снова оплачивает всю 9B».** Общая подпись действительно может измениться, но есть отдельные этапы, native checkpoints и источник-квалифицированные принятые ответы. Новый stage miss не равен новому платному запросу для каждого фрагмента. Изменение смысла редакторского профиля всё же может требовать нового отбора.
4. **«DeepSeek автоматически делает четыре параллельных запроса».** В текущем `DeepSeekVision` нет `supports_query_batch/query_many`. `ThreadPoolExecutor(max_workers=1)` обеспечивает отзывчивость отмены одного HTTP-запроса. Координатор независимых контрактов включён в управляемом Antigravity. Это техническое различие подключения, а не разные правила анализа.
5. **«Достаточно JSON с dramatic_condensation=true».** Неполный объект не проходит `load_profile`: нужны version, policy и все остальные поля профиля. Готовый `DRAMATIC_PROFILE` существует, но один флаг не гарантирует иной монтаж.
6. **«Новый редакторский профиль можно сравнить через plan_only без нового VLM».** `cached_analysis` проверяет совместимость профиля, источника и сохранённого анализа. plan_only подходит для совместимых изменений планирования, например предпочтительного числа частей; изменение семантики отбора не является бесплатным перепланированием.
7. **«plan_only всегда мгновенный и всегда работает».** Он не вызывает модели и не экспортирует видео, но требует подходящего завершённого анализа и проходящих локальных gates. Для незавершённого анализа может выдать конкретную ошибку совместимости/полноты.
8. **«Проверки global и selection полностью одинаковые».** Одна уточняет понимание/конфликты, другая требует полного исходного keep/drop-доказательства. Лишние повторения устранены условиями запуска и кэшем; полное удаление исходных доказательств не обосновано.
9. **«460–1200 запросов и 50–60% токенов».** Такие универсальные оценки представленным аудитом не доказаны. Ни объём текста, ни число файлов/units не равны оплаченным токенам. Нужен фактический usage завершённого сопоставимого запуска.
10. **«Четыре-пять обязательных загрузок llama.cpp».** Для обычного локального маршрута утверждение устарело после `AnalysisVisionSessions`.

## Подтверждённые оставшиеся ограничения

| Приоритет | Ограничение | Следующий осмысленный шаг |
| --- | --- | --- |
| Высокий | Точечное восстановление изменившейся смысловой границы ещё не поддержано безопасным native API. | Реализовать пересмотр одной границы с ближайшими соседями и инвалидацией только затронутого владения. Сейчас проблема остаётся явной; полный повтор серии не запускается. |
| Высокий | После изменения исходного доказательства нет безопасного частичного объединения story_structure/dialogue_relations между владельцами. | Пересчитать изменённые owners и зависимые endpoints, объединить с точно совместимым принятым графом. До этого изменённые owners остаются unresolved, остальные сохраняются. |
| Средний | Для текста связей есть кэш пакетов, но нет полного независимого пересчёта каждого owner при произвольном изменении соседних данных. | Ввести точную зависимость owner→доказательства/контекст/связи и повторно использовать принятые части; не просто убрать CURRENT из обязательной coverage. |
| Средний | Кэш framing хранится на уровне события и его списка samples. | При необходимости добавить принятую идентичность отдельного sample/соседства, чтобы изменение одного sample не повторяло прочие. Сам отправляемый запрос уже мал: локальная полоска кадров/текущая фраза. |
| Продуктовый | В действующем задании включён balanced-профиль: preserve_reactions=true, preserve_humor=true, dramatic_condensation=false. | Менять намерение монтажа отдельной настройкой и оценивать фактический результат. Экономия токенов и агрессивность вырезания — разные настройки. |
| Продуктовый | `reaction_or_humor` в нескольких guards обрабатывается через preserve_reactions OR preserve_humor. | Если нужны независимые настройки, разделить тип реакции/юмора в решениях и валидации. Выключение preserve_reactions при включённом юморе сейчас не гарантирует снятия всех защит реакций. |
| Продуктовый | В локальном story-проходе остаются три OMISSION_REASONS; глобальный story уже умеет дополнительные причины. | Расширять причины согласованно с независимым доказательством удаления, профилем и кэшем. Добавление слова slow_exposition в enum само по себе не доказывает безопасное удаление. |
| Требует измерения | Реальная художественная плотность и экономия токенов на полном новом результате. | Сравнить готовый монтаж с исходником и реальным usage. Тесты механизма не подтверждают качество новых решений модели или конкретный процент экономии. |

Подъём importance-порога или снижение confidence не устраняет отсутствие исходных доказательств. `resolve_continuity` может возвращать реальную необходимую причину/ответ; его нельзя объявлять ошибкой только по факту восстановления материала.
