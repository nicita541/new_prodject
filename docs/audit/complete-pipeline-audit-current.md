**DeepSeek и Antigravity считаем одним облачным режимом анализа.** Это два взаимозаменяемых подключения: одинаковые вопросы, выбор фрагментов, минимизация данных и продолжение. В доказательствах сохраняется фактический автор ответа.

## Что в присланном аудите неверно или требует оговорки

1. **«Ошибка VLM сохраняет всё событие».** Текущий `minimal_semantic_context` оставляет пересечение прежнего выбора с конкретными положительными доказательствами. Он выставляет `whole_scene_last_resort=false`; неизвестный материал не становится принятым.
2. **«Global review ставит всем importance=4».** В `validated_event` это резервное значение для отсутствующей/неверной оценки, а не обязательное решение для каждого события. Само завышение реальных оценок модели надо проверять на её ответах.
3. **«Каждая смена настроек снова оплачивает всю 9B».** Общая подпись действительно может измениться, но есть отдельные этапы, native checkpoints и источник-квалифицированные принятые ответы. Новый stage miss не равен новому платному запросу для каждого фрагмента. Изменение смысла редакторского профиля всё же может требовать нового отбора.
4. **«DeepSeek автоматически делает четыре параллельных запроса».** В текущем `DeepSeekVision` нет `supports_query_batch/query_many`. `ThreadPoolExecutor(max_workers=1)` обеспечивает отзывчивость отмены одного HTTP-запроса. Координатор независимых контрактов включён в управляемом Antigravity. Это техническое различие подключения, а не разные правила анализа.
5. **«Достаточно JSON с dramatic_condensation=true».** Неполный объект не проходит `load_profile`: нужны version, policy и все остальные поля профиля. Готовый `DRAMATIC_PROFILE` существует, но один флаг не гарантирует иной монтаж.
6. **«Новый редакторский профиль можно сравнить через plan_only без нового VLM».** `cached_analysis` проверяет совместимость профиля, источника и сохранённого анализа. plan_only подходит для совместимых изменений планирования, например предпочтительного числа частей; изменение семантики отбора не является бесплатным перепланированием.
7. **«plan_only всегда мгновенный и всегда работает».** Он не вызывает модели и не экспортирует видео, но требует подходящего завершённого анализа и проходящих локальных gates. Для незавершённого анализа может выдать конкретную ошибку совместимости/полноты.
8. **«Проверки global и selection полностью одинаковые».** Одна уточняет понимание/конфликты, другая требует полного исходного keep/drop-доказательства. Лишние повторения устранены условиями запуска и кэшем; полное удаление исходных доказательств не обосновано.
9. **«460–1200 запросов и 50–60% токенов».** Такие универсальные оценки представленным аудитом не доказаны. Ни объём текста, ни число файлов/units не равны оплаченным токенам. Нужен фактический usage завершённого сопоставимого запуска.
10. **«Четыре-пять обязательных загрузок llama.cpp».** Для обычного локального маршрута утверждение устарело после `AnalysisVisionSessions`.

## Исправления после полного аудита

| Область | Теперь |
| --- | --- |
| Спорная смысловая граница | Проверяется сохранённая спорная граница и ближайшие реальные исходные соседи. Пересобираются только окна, которые она действительно разделила. |
| Сюжетные и диалоговые связи | Полный результат объединяется локально; отправляются только отсутствующие вопросы изменённых владельцев и реальных зависимых концов связей. Исходная компактная упаковка первых запросов сохранена. |
| Изменение списка сцен | Прежние CURRENT-группы привязаны к исходным интервалам; вставка/разделение не сдвигает все последующие пакеты. |
| Кадрирование | Сохраняются исходные ответы по отдельным samples; зависимые held/fallback-решения вычисляются заново. Ожидающее кадрирование новых окон сохраняется до разрешения отбора и при продолжении. |
| Исправленная геометрия | Отдельный источник-квалифицированный overlay связывает точные derived events со сценами. Исходные сцены и visual journal не перезаписываются. |
| Конец части | Существующие классификация и независимое подтверждение вызываются только для фактической неподтверждённой границы. Повтор той же отрицательной проверки берётся из кэша. |
| Реакции и юмор | Типизированные реакции следуют preserve_reactions, комическая развязка — preserve_humor. Неопределённые старые флаги остаются консервативными. Профиль пользователя не изменён. |
| Сетевая ошибка DeepSeek | Автоматического повторного HTTP-запроса нет: сервер уже мог его обработать. Допускается одна компактная коррекция формата ответа. |
| Локальная ошибка плана | Исправление плана не открывает модельную сессию, если вопрос к модели отсутствует. plan_only по-прежнему не запускает inference. |
| Переключение облака | DeepSeek-plan и Antigravity совместимы также для готового snapshot. Источник, профиль, разметка речи, layout и содержимое всё равно проверяются; фактический автор результата сохраняется. |

## Подтверждённые оставшиеся ограничения

| Ограничение | Поведение |
| --- | --- |
| Исторический граф без точных dependency contracts | Старые строки не получают новую подтверждённость автоматически. Вне разрешённого участка запросов нет; недостающие доказательства остаются явными. |
| Устаревшая общая requires-зависимость без исходных unit refs | Нельзя угадать, какой новый дочерний фрагмент является причиной. Зависимость восстанавливается по новым подтверждённым source relations или остаётся unresolved. |
| Первое понимание ещё неизвестного источника | Нужны первичные исходные факты и связи; кэш и точечные проверки не заменяют их выдуманными решениями. |
| Намерение монтажа | В действующем задании balanced: preserve_reactions=true, preserve_humor=true, dramatic_condensation=false. Экономия токенов не переключает профиль монтажа. |
| Причины удаления | Три локальные OMISSION_REASONS сохранены. Добавление причины без независимого исходного подтверждения не является безопасным исправлением. |
| Художественное качество и процент экономии | Требуют сопоставимого завершённого монтажа и реального usage. Механические тесты не подтверждают качество новых суждений модели или универсальный процент экономии. |

Подъём importance-порога или снижение confidence не устраняет отсутствие исходных доказательств. `resolve_continuity` может возвращать реальную необходимую причину/ответ; его нельзя объявлять ошибкой только по факту восстановления материала.
