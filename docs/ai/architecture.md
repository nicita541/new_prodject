# Architecture

Current provider contract (2026-10-05, ADR-0015): montage calls use cached direct DeepSeek requests with at most two retries. Job creation, retry, browser readiness and provider checks do not read or update money ledgers or balances. Historical monetary components described below are retired from active data flow; `/api/deepseek/balance` returns disabled metadata, and connection checking uses `/models`. Cancellation, TLS/authentication protection, strict output schemas, OP ownership and bounded export concurrency remain.

Keep this document focused on stable system structure.

## System overview
<!-- What the project does and its major runtime pieces. -->
Russian-dubbed anime condensation into chronological original-audio portrait clips with variable scene-based lengths and a 120-second processing ceiling. Input media remains unchanged. The default local provider is offline after explicit setup; optional DeepSeek analysis explicitly sends text and sampled frames remotely.

## Components and ownership
<!-- Major modules/services/scenes/packages and what each owns. -->
- FastAPI server/static UI: source import/registry, persistent history, single-job ownership, status, cancellation/retry, HTTP range output playback.
- Worker: one job per child process, Windows Job Object confines all child processes; cancel terminates only owned descendants.
- Analysis: FFprobe/FFmpeg preparation and isolated faster-whisper speech process, including bounded re-recognition of suspicious VAD gaps. Sequential llama.cpp sessions use Qwen 4B for visual events, Qwen 9B with thinking for source-unit condensation/title and credit checks/global continuity, then Qwen 9B without thinking for temporal focus. Closing novelty compares late silent units with earlier retained facts; only current-image evidence permits removing title narration. Focus compares neighboring frames without crossing shot/cut boundaries, samples motion at gaps up to four seconds and prioritizes action without speech; uncertain focus holds a prior subject only within the same shot and selected interval, otherwise uses the current visible subject or center with an explicit warning.
- Planner: dependency closure and chronological word-safe timeline with verified scene endings, a soft 90-second target and a 120-second processing ceiling. Short complete replies move to the next part instead of filling a remainder with a mid-phrase split. After all model stages close, the renderer may export at most two independent final FFmpeg parts concurrently; the coordinator alone owns ordered checkpoints, progress, validation, and atomic publication. Cancellation/failure stops dispatch and drains owned subprocesses, preserving validated completed parts for resume. Run manifests record source/Git/runtime-code and semantic identities plus stage/part timings; cache reuse keeps unknown legacy encoder provenance unknown. Exports retain original audio, focus crop, burned ASS, and remapped SRT. Focus jumps on actual shot boundaries and smooths within a shot. Subtitle wrapping measures the actual font width. Obsolete checkpoint-verified exports are archived only after successful replacement.
- Cover context: after final planning, the selected analysis provider automatically creates optional per-part Russian title, short setup synopsis and image prompt from retained subtitles and six chronological source-frame samples inside the final cuts. Dialogue is supplied without speaker attribution; summaries with unreliable character names are not sent to this generation stage. A separate signed cache follows source identity, cuts, text, provider and model identity. Failure falls back to an extractive description without blocking export; fallback scene summaries are limited to events wholly contained in the part. Review GET requests derive legacy fallback descriptions locally and never start inference. Cover metadata does not enter export fingerprints or change MP4s.

## Data and control flow
<!-- Important flows that cross component boundaries. -->
Local scene understanding records separate semantic, visual and context confidence. Uncertainty triggers fresh dense-frame recovery before condensation; unresolved scenes retain bounded factual context. Independent global visual verification can confirm or correct local hypotheses from original current images, while preserving confirmed source exclusions and full decision provenance. See decisions/0020-scene-recovery-and-global-verification.md.

Opaque source ID → job/source JSON and editorial profile → probe/audio/transcript/shots → source visual descriptors → semantic scenes → word-safe units and scene-owned technical analysis chunks → visual checkpoints → story refinement/dialogue rescue → full-episode production sequences → eyecatch exclusions → title/closing checks → independent source-role proofs → global dependencies/speech-context protection → pacing → temporal focus checkpoints → events/story → montage plan (hook/cliffhanger boundaries) → smart audio analysis & Content ID ducking → validated MP4/SRT → registered API files. Retry reuses validated intermediates and exports only for matching source/settings fingerprints. Derived event caches include transcript, shots, scenes, model identity, editorial profile, semantic stage versions, and production image-page capability. Storyboard samples are clamped to actual video-frame timestamps, independently of a longer audio/container tail; source bounds are cached by resolved path, size, and mtime. Individual extracted storyboard frames are keyed by source identity and actual timestamp, preventing stale pixels under new labels after ASR repair. Scene context and storyboard selection reasons are audited in `diagnostics/pipeline`; see decisions/0019-semantic-scene-pipeline.md.

Story condensation receives current images for all scenes and retains whole selected source units, preserving silent setup and reactions around speech. Unit coverage takes priority in storyboard sampling. Opening/ending checks compare bounded current units with nearby original production-anchor frames in source chronological order; a text-free montage unit requires visual sequence membership, not silence or adjacency. Real narrative and dialogue remain protected. Short branding/title candidates undergo one screen per event followed by independent per-unit image confirmation; uncertain evidence preserves footage. See decisions/0008-visual-unit-continuity.md.

`app/editorial.py` owns the validated per-job `editorial-settings.json` profile independently of rendering/provider settings. Balanced defaults preserve almost all reactions and humor; disabling dwell/repetition removal is enforced by domain guards. A story omission becomes an authoritative current-story exception only after an independent proof has exact boolean ownership, finite confidence at least 0.9, and positive new-action or profile-protected reaction evidence. The proof and bounded source-unit ranges are serialized and checked on cache reuse. Closing, source-role, sequence, global-selection, pacing, and planner stages preserve those verified ranges; tentative restoration/fallback alone does not. Original overlapping production clusters contribute a monotone union of credit exclusions, with the verified ranges subtracted from broad exclusions so confirmed nonstory material around them remains removable. `app/source_roles.py` reviews suspicious credit/tail units with before/current/after evidence and a separate skeptical confirmation, binding speech quotes to supplied ASR and song/artifact claims to actual confirmed credit spans. See decisions/0012-editorial-policy-and-source-roles.md and decisions/0013-verified-story-and-render-contract.md.

## External integrations
<!-- APIs, services, SDKs, storage, platform integrations. -->
Optional DeepSeek image/text JSON adapter, selected and persisted per job. API key stays in ignored data/settings. HTTPS host is fixed; redirects/proxies disabled. Before each paid request, compare a conservative request cost estimate with the verified account balance. A durable ledger records reservations and known usage and blocks further paid calls after unknown failures; the user removed account/attempt amount ceilings. Explicit retry advances attempt identity while cumulative charges and replay guards remain. Independent provider_balance snapshots/windows expose provider-sourced account balance/decrease with timestamps, partial coverage and funding-adjustment flags. They are not per-key invoices and do not mutate paid accounting. Peak-rate token estimates remain separately labeled. Content-addressed validated response caching avoids paid repeats; default local jobs never invoke the remote client.

Explicit hybrid jobs wrap each sequential local session: local inference first, remote review only for uncertainty, invalid answers, low focus confidence (.75), unconfirmed visible speech or classifier confidence below the existing .85 threshold. A job review journal records successful and unresolved requests by actual evidence/model/schema identity before remote submission. Remote failure disables further paid attempts for the job while local work continues; exact cached remote answers remain usable. Unresolved counts and fallback warnings propagate into the montage plan/UI. All affected stage checkpoints include the hybrid routing profile, so prior local-only decisions are not mistaken for reviewed decisions.

## Architectural constraints
<!-- Rules that are expensive or dangerous to violate. -->
Everything lives inside the workspace, including portable runtimes, GPU DLLs, model weights, caches and temp files. One model stage at a time for 8GB VRAM. HTTP APIs bind to loopback and enforce host/origin checks; model output can choose supplied source IDs but cannot execute commands or select arbitrary timestamps.

Explicit `deepseek_plan` uses the remote model for initial multimodal events, source-unit selection, title/credit removal and global continuity, but routes final temporal focus to local Qwen9. Provider identities isolate derived decisions from local/hybrid/full-cloud checkpoints. Domain validators check partitions and existing-event dependencies before accepting a remote answer. Direct requests have at most two retries; success-only caching, cancellation, authentication and TLS checks remain. Monetary preflight, ledger reservations and global unknown-usage halts are retired; see [decision 0015](decisions/0015-simple-provider-retries.md). New-job UI offers `deepseek_plan` and `local`; historical provider values remain readable. Seven checkpoints show the real stage and its local/API routing.

Whole-production authority covers independently bounded and anchored OP and explicitly pure ED. A low-confidence typed production candidate can trigger one dense independent boundary review, but deletion still needs final confidence at least 0.85 and verified boundaries/strong anchors. Pure ED additionally requires `wholly_nonstory=true` with no interior narrative exceptions; actual current-episode story outside the final boundary remains protected. Strict OP v8 proofs are readable for compatibility, while ED authority requires the current proof shape/version.

Named per-job rendering settings select portrait focus or a complete sharp source frame on a blurred 9:16 background, plus classic/accent captions. Whole-frame rendering skips speaker-coordinate inference. Image-evidenced pacing reviews speech-free margins with interval and before/after frames, neighboring replies and actual retained facts. Only evidenced waiting, neutral scenery and repetition without story change can be removed; consequential action/reaction and speech handles remain. Repetition needs a retained witness. Dedicated title classifiers own all production-credit removals. Pacing/layout have final-event signatures; unchanged paid request content stays reusable. Render fingerprints include presentation settings. Accounting recovery preserves costs/replay guards; see decisions/0005-episode-budget-recovery.md.

The planner restores recognized dialogue for legacy/fallback selection, while validated whole-unit partitions can intentionally omit redundant exchanges. Selected replies still expand to complete speech with bounded lead/tail context. Explicit global exclusions require reasons/evidence; dependencies and verified question/prefix context rescue needed prerequisites. Confirmed title/credit/review source exclusions are subtracted afterward. Part splitting prefers independently checked closure/cliffhanger boundaries over equal durations. Optional app.endings metadata is derived from retained source boundaries and exact neighboring dialogue in bounded output-time neighborhoods. Unsupported boundaries have explicit fallback warnings. Pacing reviews whole silent shots and long sequences across analysis windows; neutral-view evidence replaces tentative atmosphere labels on those ranges. See decisions/0017-variable-parts-and-sequence-pacing.md; decisions/0009-explicit-condensation-balanced-parts.md describes the superseded balancing policy. A single source-time timeline groups cuts by part and exposes omitted gaps and output offsets. Original playback uses registered bounded loopback range streaming; see decisions/0006-dialogue-and-source-timeline.md.

`app.library.Library` adds persistent anime/episode ownership above existing jobs, under the manager mutex. `data/library.json` stores project/episode identities, one source per episode, saved settings and legacy associations; new jobs carry episode_id before worker startup. Browser `library.js` routes project library → anime episodes → editing/processing → review. The existing `app.js` controls are reused on the respective screen. Review attempts and source selection are scoped to the selected episode; catalog edits alone do not invoke models. See decisions/0007-anime-episode-library.md.

Project/episode deletion archives catalog records only. The trash screen restores them after checking current ownership conflicts; deleting a project hides its children without altering their individual archive flags. Job/source/export storage and ledger remain independent and untouched. Active processing blocks archiving its episode or parent.
