# Architecture

Current provider contract (2026-10-05, ADR-0015): montage calls use cached direct DeepSeek requests with at most two retries. Job creation, retry, browser readiness and provider checks do not read or update money ledgers or balances. Historical monetary components described below are retired from active data flow; `/api/deepseek/balance` returns disabled metadata, and connection checking uses `/models`. Cancellation, TLS/authentication protection, strict output schemas, OP ownership and bounded export concurrency remain.

Keep this document focused on stable system structure.

The only interface is **Studio Edition**: four assets under `frontend/public` are copied to `frontend/dist` by `frontend/scripts/build-studio.mjs` using native Node, and served through `app.studio_routes`. The bridge loads real backend data; there are no seeded catalogs, fake plans or demo media. React, legacy static UI and the reference demo have been removed. The detailed hierarchical map and storage registry are in [the application audit](../audit/README.md).

Launcher identity covers every `app/*.py` module and all four active Studio assets, so a changed backend is not silently reused. `POST /api/studio/shutdown` verifies this identity, refuses active processing/exports and blocks new tasks while shutting down; `остановить_Кадр.bat` invokes the idle-only launcher. See [decision 0027](decisions/0027-idle-studio-shutdown.md).

## System overview
<!-- What the project does and its major runtime pieces. -->
Russian-dubbed anime condensation into chronological original-audio vertical clips with variable scene-based lengths and a 120-second ceiling per planned output part. This is not an input-duration or wall-clock processing limit. Input media remains unchanged. The local provider is offline after explicit setup; optional DeepSeek analysis explicitly sends text and sampled frames remotely. Compatibility API callers default to local/portrait/classic; the active Studio editor explicitly defaults to DeepSeek-plan/cinema/accent for a new selection.

## Components and ownership
<!-- Major modules/services/scenes/packages and what each owns. -->
- FastAPI server: API contracts, security middleware and application lifecycle. `studio_routes` exclusively owns Studio assets and screen deep links; its fallback is registered after concrete API routers. `library` and `jobs` own persisted catalog/source/job state; HTTP handlers delegate to them.
- Worker: one job per child process, Windows Job Object confines all child processes; cancel terminates only owned descendants.
- Analysis: FFprobe/FFmpeg preparation and isolated faster-whisper speech process, including bounded re-recognition of suspicious VAD gaps. Sequential llama.cpp sessions use Qwen 4B for visual events, Qwen 9B with thinking for source-unit condensation/title and credit checks/global continuity, then Qwen 9B without thinking for temporal focus. Closing novelty compares late silent units with earlier retained facts; only current-image evidence permits removing title narration. Focus compares neighboring frames without crossing shot/cut boundaries, samples motion at gaps up to four seconds and prioritizes action without speech; uncertain focus holds a prior subject only within the same shot and selected interval, otherwise uses the current visible subject or center with an explicit warning.
- Analysis boundaries: `analysis` coordinates perception and source analysis; `editorial_pipeline` coordinates selection, endings, story and dialogue passes inside an already owned provider session. `analysis_result` assembles records/profiles/diagnostics without model calls. `final_quality` inspects source proofs and reports failures without repairing them. `quality_recovery` performs targeted repair; `pipeline` alone owns recovery limits, replanning, checkpoints and render dispatch. Shared `source_text`, `cancellation` and `content_identity` provide one implementation for transcript matching, cooperative cancellation and strict JSON digests. Different existing digest encodings remain distinct. Refactored source and helper modules participate in semantic cache identities; no identities are frozen to hide code changes. See [decision 0032](decisions/0032-studio-only-and-pipeline-ownership.md).
- Planner: natural source story arcs precede candidate selection and chronological word-safe part grouping. Dependencies request bounded causal context; factual state paths can restore individual action units without transitive whole-scene restoration. Preferred part count is a soft objective below semantic integrity, with a soft 90-second target and a 120-second processing ceiling. Immediate question/answer context is preserved even under retention pressure. Short complete replies move to the next part instead of filling a remainder with a mid-phrase split. After all model stages close, the renderer may export at most two independent final FFmpeg parts concurrently; the coordinator alone owns ordered checkpoints, progress, validation, and atomic publication. Cancellation/failure stops dispatch and drains owned subprocesses, preserving validated completed parts for resume. Run manifests record source/Git/runtime-code and semantic identities plus stage/part timings; cache reuse keeps unknown legacy encoder provenance unknown. Exports retain original audio, focus crop, burned ASS, and remapped SRT. Focus jumps on actual shot boundaries and smooths within a shot. Subtitle wrapping measures the actual font width. Obsolete checkpoint-verified exports are archived only after successful replacement.
- Cover context: after final planning, the selected analysis provider automatically creates optional per-part Russian title, short setup synopsis and image prompt from retained subtitles and six chronological source-frame samples inside the final cuts. Dialogue is supplied without speaker attribution; summaries with unreliable character names are not sent to this generation stage. A separate signed cache follows source identity, cuts, text, provider and model identity. Failure falls back to an extractive description without blocking export; fallback scene summaries are limited to events wholly contained in the part. Review GET requests derive legacy fallback descriptions locally and never start inference. Cover metadata does not enter export fingerprints or change MP4s.

## Data and control flow
<!-- Important flows that cross component boundaries. -->
Production source-only perception precedes grouping: measured perceptual/background vectors, intra-shot optical flow, PCM audio/ASR and fade/black evidence supplement all raw shot candidates with independent proposals. Cheap boundary triage sends only ambiguous candidates to current-source visual verification. Trusted location/state transitions create scene edges; camera recurrence remains one scene. Production strips supplied semantic answers and retains weak proofs as unresolved evidence. Label-free actual-model quality runs use `scripts/run_raw_video_quality.py`; pure supplied-state tests prove isolated logic only. See decisions/0023-source-only-perception-and-semantic-boundary-verification.md.

Raw shot candidates remain available after adaptive montage suppression. Semantic grouping can recover suppressed location/state boundaries from source frames. Initial factual episode profiles tune grouping; refined profiles derive source-bounded retention budgets from speech, visual changes and confirmed actions. Dramatic planning measures actual selected material and preserves validated source units. See decisions/0021-adaptive-episode-profile.md.

`story_structure_pass` derives unit-scoped roles, relations, canonical facts and arcs from accepted source proofs and exact ASR. Several arcs may share a semantic scene. `dialogue_relations` covers CURRENT units and identifies required exchanges independently of punctuation. `story_structure` exposes inferred arcs to planners; `source_continuity` restores actual evidenced units and reports unresolved gaps. `continuity_verification` inspects omitted original footage, including omitted units inside retained parents. `final_quality` checks analysis before planning and every fresh/cached plan before rendering, with at most three automatic recovery passes. Unresolved continuity blocks export. `planner_audit` records source timeline, candidate scores, bridges, transitions and part alternatives. Component identities include these passes and their source/prompt policies. See [decision 0025](decisions/0025-source-structure-and-pre-render-quality.md).

Local scene understanding records separate semantic, visual and context confidence. Uncertainty triggers fresh dense-frame recovery before condensation; unresolved scenes retain bounded factual context. Independent global visual verification can confirm or correct local hypotheses from original current images, while preserving confirmed source exclusions and full decision provenance. See decisions/0020-scene-recovery-and-global-verification.md.

Opaque source ID → job/source JSON and editorial profile → probe/audio/transcript/shots → source visual descriptors → semantic scenes → word-safe units and scene-owned technical analysis chunks → visual checkpoints → story refinement/dialogue rescue → full-episode production sequences → eyecatch exclusions → title/closing checks → independent source-role proofs → global dependencies/speech-context protection → pacing → source selection/endings/structure/dialogue checks → temporal focus checkpoints → events/story → montage plan and final quality gate → optional per-part title/synopsis/image prompt → transcript-based background music ducking → validated MP4/SRT → registered API files. The ducking heuristic does not identify copyrighted recordings or provide Content ID protection. Retry reuses validated intermediates and exports only for matching source/settings fingerprints. Derived event caches include transcript, shots, scenes, model identity, editorial profile, semantic stage versions, and production image-page capability. Storyboard samples are clamped to actual video-frame timestamps, independently of a longer audio/container tail; source bounds are cached by resolved path, size, and mtime. Individual extracted storyboard frames are keyed by source identity and actual timestamp, preventing stale pixels under new labels after ASR repair. Scene context and storyboard selection reasons are audited in `diagnostics/pipeline`; see decisions/0019-semantic-scene-pipeline.md.

The user explicitly chose to retain the current mid-episode eyecatch heuristic and document its risk. Unlike source-evidenced OP/ED/title classifiers, `app/eyecatch.py` uses duration, position, speech density and shot boundaries without a branding-image check; it clears selected ranges for candidates. This can exclude a quiet story event on inputs of at least 300 seconds. Short 120/180-second benchmarks do not exercise this branch. `semantic_identity._COMPONENTS` currently omits eyecatch, so changes to this policy need explicit derived-version invalidation until dependency coverage is expanded. These are documented code risks, not evidence that a particular user scene was lost.

Source optical flow and accepted editing cuts remain separate profile measurements. Analysis persists one finalized `episode_profile` after semantic selection; the dramatic planner consumes that exact snapshot and retention budget. `retention_allocation` reserves source-proven mandatory transitions, then costs ranked optional ranges together with their continuity context. Its audit preserves required bridge provenance across subsequent allocations and explains mandatory overflow; suppressed shot candidates do not assert motion. See [Stage 3](../semantic-montage-stage3.md).

Story condensation receives current images for all scenes and retains whole selected source units, preserving silent setup and reactions around speech. Unit coverage takes priority in storyboard sampling. Opening/ending checks compare bounded current units with nearby original production-anchor frames in source chronological order; a text-free montage unit requires visual sequence membership, not silence or adjacency. Real narrative and dialogue remain protected. Short branding/title candidates undergo one screen per event followed by independent per-unit image confirmation; uncertain evidence preserves footage. See decisions/0008-visual-unit-continuity.md.

`app/editorial.py` owns the validated per-job `editorial-settings.json` profile independently of rendering/provider settings. Balanced defaults preserve specific reactions and humor; disabling dwell/repetition removal is enforced by domain guards. A story omission becomes an authoritative current-story exception only after an independent proof has exact boolean ownership, finite confidence at least 0.9, and positive new-action or profile-protected reaction evidence. The proof and bounded source-unit ranges are serialized and checked on cache reuse. Those ownership exceptions prevent broad nonstory exclusions from swallowing established current-story material. They do not expand a later independently adjudicated selection. Original overlapping production clusters contribute a monotone union of credit exclusions, with the verified ranges subtracted from broad exclusions so confirmed nonstory material around them remains removable. `app/source_roles.py` reviews suspicious credit/tail units with before/current/after evidence and a separate skeptical confirmation, binding speech quotes to supplied ASR and song/artifact claims to actual confirmed credit spans. See decisions/0012-editorial-policy-and-source-roles.md, decisions/0013-verified-story-and-render-contract.md and decisions/0024-evidenced-selection-adjudication.md.

Production understanding and retention have separate confidence fields. Uncertainty triggers local, dense-context and targeted source-unit review; failures retain only previously selected positive evidence and remain explicitly unresolved. `app/selection_adjudication.py` binds concrete reaction, pause, payoff, establishing, causal-dialogue and physical-action evidence to actual CURRENT frames or exact ASR quotes. Neutral scenery and waiting have no automatic protection. High-confidence global visual keep/drop decisions can replace a complete source-unit selection; unseen or disputed coverage requires targeted review. `app/selection_gate.py` checks final confidence, ownership, concrete evidence coverage and unresolved flags after pacing; production analysis exposes the gate and planners reject unresolved results. Empty selections stay empty through later classifiers. Timeline diagnostics show specific proof and source-bounded neutral removals. See decision 0024.

Preobtained ASR is supported by `analysis-settings.json` with `transcript_mode="provided"` and `transcript_source_sha256` matching the actual source. `app/provided_asr.py` validates finite ordered source timestamps and forbids semantic answer fields. Its provenance explicitly records supplied text; it does not claim recognition or ASR repair was performed. Normal automatic speech recognition remains the default.

Before real scene analysis, the original video's decoded PTS timeline identifies intervals without a video frame. `scene_analysis.frame_backed_scenes` coalesces these intervals into an adjacent analysis scene while preserving audio, word-safe outer boundaries and source coverage. Raw detector scenes remain unchanged, and the analysis mapping records each coalesced interval's original ID/range. Bounded storyboards continue to require actual frame PTS inside their own windows. See [decision 0026](decisions/0026-frame-empty-analysis-intervals.md).

## External integrations
Manual Antigravity is an opt-in query transport for Qwen9B tasks only. KADR exports exact prompt/schema/image packets and validates official CLI JSON. Default manual mode pauses with `waiting_analysis`; opt-in file reception waits for the current packet in the same worker and continues after validation. Users separately run `scripts/run_antigravity_packet.ps1` or `run_antigravity_job.ps1`; the application never starts agy or reads its credentials. Initial4B perception retains its native identity; provider banks preserve local semantic checkpoints for rollback. See [ADR0028](decisions/0028-manual-antigravity-exchange.md), [ADR0029](decisions/0029-antigravity-file-reception.md) and [operation guide](../antigravity-manual.md).
<!-- APIs, services, SDKs, storage, platform integrations. -->
Optional DeepSeek image/text JSON adapter, selected and persisted per job. API key stays in ignored data/settings. HTTPS host is fixed; redirects/proxies disabled. Direct requests use successful-response caching and at most two retries; cancellation, authentication and TLS failures stop immediately. Runtime does not read or write historical money ledgers or balance snapshots. The compatibility balance endpoints return disabled metadata, and connection checks use `/models`. Content-addressed validated response caching avoids paid repeats; default local jobs never invoke the remote client.

Explicit hybrid jobs wrap each sequential local session: local inference first, remote review only for uncertainty, invalid answers, low focus confidence (.75), unconfirmed visible speech or classifier confidence below the existing .85 threshold. A job review journal records successful and unresolved requests by actual evidence/model/schema identity before remote submission. Remote failure disables further paid attempts for the job while local work continues; exact cached remote answers remain usable. Unresolved counts and fallback warnings propagate into the montage plan/UI. All affected stage checkpoints include the hybrid routing profile, so prior local-only decisions are not mistaken for reviewed decisions.

## Architectural constraints
<!-- Rules that are expensive or dangerous to violate. -->
Everything lives inside the workspace, including portable runtimes, GPU DLLs, model weights, caches and temp files. One model stage at a time for 8GB VRAM. HTTP APIs bind to loopback and enforce host/origin checks; model output can choose supplied source IDs but cannot execute commands or select arbitrary timestamps.

Explicit `deepseek_plan` uses the remote model for semantic boundary review, initial multimodal events, source-unit selection, title/credit removal and global continuity, but routes final temporal focus to local Qwen9. Provider identities isolate derived decisions from local/hybrid/full-cloud checkpoints. Domain validators check partitions and existing-event dependencies before accepting a remote answer. Direct requests have at most two retries; success-only caching, cancellation, authentication and TLS checks remain. Monetary preflight, ledger reservations and global unknown-usage halts are retired; see [decision 0015](decisions/0015-simple-provider-retries.md). Active Studio offers `deepseek_plan`, `local`, `hybrid` and `deepseek`; experimental provider values remain readable through compatibility code. Progress exposes the current stage and its local/API routing.

Whole-production authority covers independently bounded and anchored OP and explicitly pure ED. A low-confidence typed production candidate can trigger one dense independent boundary review, but deletion still needs final confidence at least 0.85 and verified boundaries/strong anchors. Pure ED additionally requires `wholly_nonstory=true` with no interior narrative exceptions; actual current-episode story outside the final boundary remains protected. Strict OP v8 proofs are readable for compatibility, while ED authority requires the current proof shape/version.

Named per-job rendering settings select portrait focus or a complete sharp source frame on a blurred 9:16 background, plus classic/accent captions. Whole-frame rendering skips speaker-coordinate inference. Image-evidenced pacing reviews speech-free margins with interval and before/after frames, neighboring replies and actual retained facts. Only evidenced waiting, neutral scenery and repetition without story change can be removed; consequential action/reaction and speech handles remain. Repetition needs a retained witness. Production/title/source-role classifiers own source-evidenced credit removals; the retained eyecatch heuristic is the separately documented exception. Pacing/layout have final-event signatures; unchanged paid request content stays reusable. Render fingerprints include presentation settings. Historical accounting recovery in decisions/0005-episode-budget-recovery.md is retired under ADR-0015.

The planner restores recognized dialogue for legacy/fallback selection, while validated whole-unit partitions can intentionally omit redundant exchanges. Validated selections preserve original ASR word timestamps; minimal continuity ranges bypass whole-reply/whole-scene expansion. Immediate question/answer pairs restore only missing source dialogue, with any necessary bridge-budget exception recorded. Explicit global exclusions require reasons/evidence; direct dependencies and verified question/prefix context request bounded prerequisites. Confirmed title/credit/review source exclusions are subtracted afterward. Part splitting compares natural exits and alternative counts, rejecting boundaries inside retained speech, question/answer exchanges, consequential action and protected story ranges even when labeled cliffhanger. Optional app.endings metadata is derived from retained source boundaries and exact neighboring dialogue in bounded output-time neighborhoods. Unsupported boundaries have explicit fallback warnings. Pacing reviews whole silent shots and long sequences across analysis windows; neutral-view evidence replaces tentative atmosphere labels on those ranges. See decisions/0022-story-arcs-minimal-context-and-cache-signatures.md and decisions/0017-variable-parts-and-sequence-pacing.md; decisions/0009-explicit-condensation-balanced-parts.md describes the superseded balancing policy. A single source-time timeline groups cuts by part and exposes omitted gaps and output offsets. Original playback uses registered bounded loopback range streaming; see decisions/0006-dialogue-and-source-timeline.md.

`app.library.Library` adds persistent anime/episode ownership above existing jobs, under the manager mutex. `data/library.json` stores project/episode identities, one source per episode, saved settings and legacy associations; new jobs carry episode_id before worker startup. Studio Edition is the sole library interface. `GET /api/library` returns separate flat `projects` and `episodes` arrays, with `{id,status,created_at}` job references on each episode. Parent ownership and `archived_at` determine visibility: children of archived projects are represented by their project trash entry, while individually archived episodes appear only under active parents. Review accepts completed references belonging to the selected episode; catalog edits alone do not invoke models. See decisions/0007-anime-episode-library.md; current backend/Studio contracts are checked by API and Studio integration tests.

Project/episode deletion archives catalog records only. The trash screen restores them after checking current ownership conflicts; deleting a project hides its children without altering their individual archive flags. Job/source/export storage remains independent and untouched; runtime does not use historical monetary ledgers. Active processing blocks archiving its episode or parent.

Finishing profiles are stored outside `data`, in `finishing/episodes/<episode_id>.json`; caption overrides and isolated preview/export task files live in `data/jobs/<job_id>/finishing`, with export pointers under `finishing/exports-index`. Backup must include both trees and original media. Finishing reuses completed source plans without model inference, never replaces base outputs, and uses revisions for editor saves. It allows at most three queued/active tasks and one finishing render at a time; active finishing blocks new analysis and vice versa. See [storage registry](../audit/storage-and-modules.md).

Automatic ManualVision refinement uses app.antigravity_batch to collect up to four independent child contracts into one file exchange. Only the coordinator receives files/reports progress; child selection precedes its own independent omission proof. Each answer returns to its original strict schema and request cache. The separately user-started official CLI script remains outside KADR. Local/DeepSeek and manual import retain their existing sequential flow. See decisions/0030-antigravity-independent-batches.md for limits and rollback.
