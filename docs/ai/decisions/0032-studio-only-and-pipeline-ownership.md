# Единственная Studio и границы монтажного конвейера

Дата: 13 октября 2026. Статус: принято.

## Проблема

Рабочая Studio сосуществовала с React, legacy static UI и reference demo. Её скрипт содержал неиспользуемые генераторы проектов, готовых планов, MP4 и звука, а также имитацию API. После удаления этого слоя оставшаяся ссылка на `store` прерывала привязку элементов finishing-редактора. В Python сборка результата и редакторские этапы находились внутри `analysis`, а проверка качества сама вызывала анализ обратно для исправлений. Одинаковые базовые функции копировались между проходами.

## Решение

Studio остаётся единственным интерфейсом с пустым начальным состоянием, которое заполняет реальный API. Демонстрационные каталоги, планы, медиа, WebAudio-имитация и mock API удалены. `jsdom` используется только в изолированных проверках интерфейса. Тестовые fixtures не попадают в продукт и не изображают результат настоящего анализа.

Native Node builder копирует пять разрешённых assets в `frontend/dist`; React/Vite/TypeScript и их интерфейсы удалены. `studio_routes` обслуживает разрешённые assets одним обработчиком и переводит совместимые ссылки экранов на Studio. API имеет приоритет перед UI fallback. Удалённые интерфейсы дают 404, отсутствующая сборка — конкретную 503.

| Владелец | Ответственность |
|---|---|
| `server` | HTTP-контракты, безопасность, lifecycle, подключение routers |
| `studio_routes` | Статика Studio и адреса экранов; не запускает задания |
| `library`, `jobs` | Реальный каталог, источники, состояние и владение worker |
| `pipeline` | Конвейер, ограничения восстановления, checkpoints, план и экспорт |
| `analysis` | Подготовка и распознавание/восприятие, orchestration анализа |
| `editorial_pipeline` | Последовательность отбора, финала, сюжета и связей реплик |
| `analysis_result` | Сборка сохранённого анализа, профиля и диагностики |
| `final_quality` | Проверка доказательств исходника и список проблем |
| `quality_recovery` | Адресное исправление перечисленных проблем |
| `source_text`, `cancellation`, `content_identity` | Единые низкоуровневые операции без модельных сессий |

## Альтернативы и совместимость

Сохранение вторых интерфейсов оставляло дублирование и противоречило запросу пользователя. Полное переписывание server, providers и планировщиков увеличило бы риск изменения монтажа; выбран перенос конкретных обязанностей с сохранением тел функций и контрактов. Импорт функций в координатор не создаёт второй реализации. `recover_final_quality` теперь импортируется непосредственно из владельца `quality_recovery`.

Форматы заданий и ответы провайдеров не меняются. Успешные ответы, исходники и результаты не удаляются. Изменение семантического исходного кода честно меняет identity; используемые общие helpers включены в подписи соответствующих компонентов. Существующие compact/spaced JSON hashes сохраняют разные кодировки.

## Проверки и откат

Проверяются обе Studio DOM/API проверки, маршруты, редакторские и quality passes, отмена, caches и провайдеры. Обнаружение ошибки не заменяется примером результата. Откат — отдельный Git revert; пользовательское состояние не мигрируется. Новый пользовательский прогон при очистке не запускается.
