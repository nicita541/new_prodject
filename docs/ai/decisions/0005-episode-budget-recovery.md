# Episode budget and explicit uncertain-request recovery

The user clarified USD 0.10 per processing attempt, rather than across all attempts at an episode. The private ledger tags new requests with workspace-relative job and attempt identities. Legacy entries belong to attempt 1. Each explicit retry starts a new allowance; the idle-job reset API/UI also renews it without starting processing. Reservations and confirmed peak-rate charges count toward their attempt; cumulative job/account costs remain unchanged and visible. Valid cache hits are free. Before dispatch, both attempt capacity and a fresh account balance must cover the reservation. Increasing the allowance requires a new user decision. Historical requests from the single test episode remain assigned to its current job/first attempt.

Automatic paid retries remain disabled. Unknown billing halts new paid calls. The explicit recovery API requires `accept_reserved_costs=true`, retains every uncertain reservation, marks it `acknowledged_unknown` without inventing token usage, blocks its request digest, and verifies account/model availability before permitting new tasks. Completed over-reservation costs cannot use this recovery. Existing confirmed-only recovery still refuses unknown usage. Loopback host/origin protection covers both paths.

The pacing stage uses a named remote-first/local-fallback route. At the episode cap or a remote failure, its remaining visual checks run with local Qwen9; warnings disclose fallback. It never sends additional paid queries in that session after fallback. Story decisions and completed pacing answers stay checkpointed. Users can continue a job with a saved story even when cloud access is halted; changed evidence that actually requires cloud remains subject to the original billing guard.

Attempt reset is protected by the job manager mutex and rejected while any worker is active. It does not clear the account halt, blocked request digests, reservations, or caches. Rollback: remove explicit recovery and the pacing route while retaining the ledger and its reservations. No cost entries are discarded or reset.
