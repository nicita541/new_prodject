# One additional review of unresolved source views

The user authorizes rechecking missing source evidence and selecting the best supported answer. Selection adjudication therefore has an explicit `retry_unresolved` mode used by final-quality recovery. Ordinary initial selection behavior remains compatible.

Accepted source views reuse native decisions only after source SHA/ASR/shot binding, exact CURRENT unit geometry/text, actual frame times, original-image hash verification and current CURRENT-page byte equality. Original checkpoint IDs remain provenance. Current event audit and the persisted per-event audit preserve previous candidates, including untouched accepted later views after an interrupted request. Legacy source context is usable only with the previously audited continuation context.

Each unresolved view gets one persisted additional round, sending that CURRENT view and necessary neighboring evidence. Historical summaries and selected-range hypotheses are omitted. The allowance binds stable source SHA/size, CURRENT/context evidence, exact image bytes, native schema, prompt and policy. File timestamp/path changes and DeepSeek↔Antigravity switches do not create another allowance. Actual model provenance is stored separately.

A started receipt is published before dispatch. Missing/uncertain transport outcomes cannot automatically resend; a saved answer can be validated after an interrupted publication. Valid uncertain and invalid outcomes also consume the round. A changed source/evidence/schema genuinely changes the contract.

Choose a complete native-valid candidate by acceptance and weakest confidence. Never splice semantic fields from different answers, inflate confidence or lower the .9 threshold. Conflicting whole-unit views remain unresolved. Accepted old views are never rechecked just to improve their confidence. A new judge model pass is unnecessary.

Technical view splitting preserves ordinary12-frame cohorts. An indivisible word may use up to the renderer's one-page18-frame capacity only when no safe subdivision fits12. A zero-origin source window may include a verified initial stream offset within one known frame interval, while unit/ASR geometry and actual in-window PTS validation remain unchanged.

Code changes invalidate semantic identities normally. Same-job integration requires stopped Studio, backups, source-qualified native stage replay and an explicit audited migration; no code hash is frozen. New receipts do not rewrite old raw answers. Rollback restores source and migration backups with Studio idle. Fake-provider regressions verify targeting, provenance, stronger/weaker candidates, exact reply-bank reuse, no repeated round, geometry and unknown-charge handling; they do not promise model accuracy.
