## User requirements for cloud analysis

- Treat DeepSeek and Antigravity as the same cloud analysis mode in product logic, audits and future changes. They are interchangeable connection choices with identical targeting, payload and continuation rules. Switching them must preserve completed work. Keep the actual producing provider in evidence provenance and each connection's credentials/transport separate.
- Existing checks must run only for concrete needed source fragments and send only evidence needed for their question. No new model checks, whole-episode recovery or expanded retries merely to compensate for uncertainty. Initial missing source/relationship construction remains distinct from rechecking accepted work.

## Environment constraints
<!-- Supported platforms, versions, deployment constraints, generated-file rules, etc. -->
- User requires all project installs, downloads, caches, temporary files and outputs inside `F:\new_prodject`; no global installs or other drives. Use the portable interpreter `tools/python/python.exe`.
- Windows 11, RTX 5060 Ti (8GB), i5-12600KF, ~32GB RAM. ASR uses local CTranslate2 CUDA libraries; VLM uses portable llama.cpp Vulkan. Models execute sequentially in owned child processes to release VRAM; local analysis shares the 4B boundary/scene load and the 9B story/pacing/framing load, switching thinking only between sequential stages.
- Python 3.12 `tempfile.TemporaryDirectory` creates restrictive Windows ACLs in this sandbox; tests use ordinary UUID directories with inherited ACLs under project `temp`. Pytest cache provider disabled to avoid that same creation issue.

## Operational notes
<!-- Stable details that repeatedly matter during development or release. -->
- `start.bat` starts a loopback-only server at `http://127.0.0.1:8765`. Explicit `setup.bat` downloads dependencies/models; runtime never downloads automatically. Keep the server attached to the interactive Windows desktop because native folder selection for video export needs a visible dialog.
- Qwen 4B initial visual artifacts live in `models/qwen`; Qwen 9B story and final framing artifacts in `models/qwen9`. Both projectors use the filename `mmproj-F16.gguf` but have different contents and checksums. Never identify a projector solely by basename. Story uses thinking; framing disables it. Both run sequentially.
- Run checks with `tools/python/python.exe -m pytest -q`. Package pins are in `requirements.lock.txt`; downloaded wheels remain in `cache/wheels`.
- Analysis modes are persisted per job. Studio offers local, `deepseek_plan` and temporary `antigravity_manual`; older jobs may use `hybrid` or `deepseek`. Antigravity replaces9B queries with validated file packets, while local4B/ASR remain native. On explicit start/resume the worker launches the installed official CLI coordinator by default; it never reads credentials. See docs/antigravity-manual.md. In `deepseek_plan`, the remote model handles story/analysis while final framing, audio, and rendering stay local. Settings and API keys remain under ignored `data/settings`.

Do not use this file as a chat log or changelog.

- Antigravity starts use `automation.json` `{enabled:true,managed:true}` when no preference exists. Explicit disabled/manual and enabled-only/external preferences are preserved. The worker owns the fixed script and descendants, handles cooperative stop/early failure and retains accepted packet caches. Atomic Windows publications use MoveFileEx instead of ReplaceFile, avoiding destination ACL-copy requirements; transient sharing errors have bounded local retries, without repeating model requests. Google consumer-plan compatibility is not certified. UI progress uses `stage_progress` exclusively; waiting preserves the actual stage and completed predecessors.

- User-facing one-click entry is `1_Запустить_Кадр.bat` → `start.bat` → `app.launcher`. It starts a missing server, opens the page after readiness, and reuses an existing server. The UI explicitly defaults to DeepSeek-plan/cinema/accent; missing settings and legacy API callers preserve local/portrait/classic.
- The main UI is Studio Edition only (`frontend/public` → native Node builder → `frontend/dist` → `app.studio_routes`/FastAPI). React, legacy and reference demo are removed. `остановить_Кадр.bat` stops only the verified idle server and preserves data. Runtime identity includes all Python app modules and all four Studio assets. Start/setup/verification prefer workspace portable Node/npm and set temporary/npm cache paths under the workspace.
- `finishing/` at workspace root contains persistent subtitle/profile/export state in addition to `data/`; include it in backups. The hierarchical component/storage map is in `docs/audit/README.md`.
- Genuine short local measurements use `scripts/benchmark_local_pipeline.py`; clips, independent jobs and raw metrics remain under the chosen `temp/` directory. Fresh/resume phases stay separate; the wrapper prohibits DeepSeek HTTP calls. Resource samples measure the whole computer, not just the worker.
- Performance is an ongoing priority: when an analysis stage is slow, inspect request fanout, frame preparation, cache reuse and actual model timings immediately, and test concrete improvements. Preserve semantic checks and the authorized run; prepare isolated optimizations rather than silently stopping a job. The target for a genuine three-minute test is about 30 minutes.
- Early LocalVision scene analysis supports two CURRENT pages of at most 18 frames each; other providers retain the 18-frame default unless they explicitly declare a larger capacity. Keep the page ceiling separate from request capacity so frames remain readable. `bounded_storyboard.source_frame_files` batches actual-PTS decoding for inference and legacy overviews; the shared source_identity cache computes source hashes only within the process while size/mtime/ctime stay unchanged, including analysis and processing consumers. Scene analysis overlaps one upcoming uncached CURRENT chunk with inference, stops/drains its worker on failure, and keeps context/recovery and progress on the coordinator. Pipeline `image_preparation` events measure CURRENT/context/recovery/overview costs separately from model requests. Source/prompt/code changes still invalidate semantic decision checkpoints.
- Semantic boundary verification groups up to three independent comparisons for LocalVision. Each result keeps its own source ID and strict scope/flag validation; uncertain results receive the original individual BEFORE/AFTER recovery, malformed batches fall back to individual checks, and control failures propagate. Providers without an explicit batch capacity remain scalar. Original validated individual checkpoints remain reusable; new batch decisions use a separate cache namespace. Scene cache identity includes the effective batch capacity.
- Launch is not gated by an account balance, monetary spending ceiling, or uncertain-charge ledger. Compatibility balance endpoints return disabled metadata; historical monetary files are not read or changed. A DeepSeek adapter query permits one initial request and at most one compact format correction. HTTP/transport failures stop without automatic resend; an unknown server result must not create an automatic duplicate charge. Timeline source playback and cached re-export are local and do not send paid requests.
- Keep `main` as the user's stable working checkout. Future development should start from `main` in an isolated `codex/*` branch/worktree so app data and the interactive Windows folder picker remain available from the stable checkout. Before cleaning `data/`, preserve imported sources, settings, and each active episode's latest completed job and source-analysis lineage; completed job folders are also the on-disk job catalog.
- `data/library.json` is the additive anime/episode catalog; legacy jobs group by registered source identity, new jobs persist episode_id before launch. One source per active episode. Delete controls use recoverable catalog tombstones; they never remove physical media or ledger records. Restore checks identity/source conflicts.

- Import/patch helper owners directly: media_probe for shot detection, vision for sessions/storyboards, story_review for units and validators, analysis_provider for routing, json_store for persistence and source_ranges for interval algebra. No lower-level import of analysis/server; existing boundary tests enforce this. Read app/README.md before changing ownership.

- Existing active/stopped jobs can switch DeepSeek-plan ↔ Antigravity through the processing selector and one apply/continue action. The manager stops only the owned worker before copying provider checkpoints and restarting the same job; source preparation and user planning preferences remain shared. `resume:false` configures a stopped job without inference. Retained Antigravity automation/quota files are ignored by DeepSeek startup. See [ADR-0045](decisions/0045-safe-story-provider-switch.md).
- Same-job continuation preserves accepted passes/replies across switches with source/transcript/input/code validation. Legacy migration is explicit and one-time. `continuation/control.json` with `cache_only:true` is exclusively for isolated offline reconstruction, never a live worker. See [ADR-0046](decisions/0046-provider-neutral-accepted-continuation.md).
- New jobs default to economy mode: optional global visual recheck, pacing, silent-sequence editing and ending refinements skip new model calls. Strict selection/story/dialogue and export gates remain. The processing switch remembers the episode preference; a stopped job stays stopped. Full/economy final caches differ, but matching accepted individual passes/replies remain reusable. See [ADR-0047](decisions/0047-economy-analysis-checks.md). Economy now scopes remaining checks to draft montage units plus required context, after exact accepted-prefix reuse. Source discovery still surveys the episode; drafts cannot export and unreviewed footage stays outside final cuts. Actual episode duration must survive filtering. Existing credit/title/closing/source-role checks use detected regions plus five-second whole-unit context; unaffected windows skip those callbacks and show as not needed. No new model pass is added. See [ADR-0048](decisions/0048-needed-fragment-review.md).

- DeepSeek selection wire text is compacted separately from canonical accepted-request identity. Preserve full native validation, unchanged source images, old expanded response-cache lookup and explicit offline stage migration when adapter code changes. See [ADR-0049](decisions/0049-compact-selection-wire-requests.md).

- Needed-data policy applies to all providers/modes; silence/position/importance alone do not trigger specialist rechecks. Preserve exact accepted contracts, source-time context, whole-unit targets and original media IDs. JSON/source retries remain compact. Scoped boundary recovery rebuilds changed CURRENT windows only; relation recovery reuses exact native dependencies and preserves initial packed batches/cohort boundaries. Raw framing samples and negative boundary/ending decisions are reusable. Missing legacy contracts and primary uncertainty stay unresolved; never auto-rebuild the whole episode. See [ADR-0050](decisions/0050-needed-data-for-all-model-checks.md) and [ADR-0051](decisions/0051-scoped-repair-and-exact-request-reuse.md).
